# RUN30 Native — iPhone без Mac и App Store

## Что включено

Нативное iOS-приложение **SwiftUI + Core Location** (iOS 16+), совместимое с существующим RUN30 Cloud v2/v3:

- 26 недель и 4 тренировки в неделю (вторник, четверг, суббота, воскресенье);
- GPS-маршрут, дистанция, активное время и средний темп, карта MapKit;
- старт / пауза / продолжение / завершение, сохранение черновика при сбое;
- **фоновое получение координат во время начатой тренировки** при выключенном экране (включён `UIBackgroundModes: location` и `allowsBackgroundLocationUpdates`);
- журнал, ручной ввод результатов, удаление записи, GPX-экспорт;
- авторизация в **том же Supabase**, что используется на RUN30 Web;
- локальное хранение и очередь отправки с повторной синхронизацией, обнаружение конфликтов.

**Не является готовым IPA:** это исходный проект и GitHub Actions workflow для получения неподписанного IPA. Компиляция для iOS требует Xcode на macOS — в этом варианте сборка происходит на облачном macOS-исполнителе GitHub Actions. Без GitHub / macOS-компиляции исходники установить на iPhone нельзя.

## 0. Что потребуется

1. Компьютер **Windows 11** с доступом в интернет.
2. **iPhone с iOS 16 или новее**, USB-кабель передачи данных.
3. Аккаунт **GitHub** и **бесплатный Apple Account**.
4. **Sideloadly** для Windows (официальный сайт: https://sideloadly.io/).
5. Уже используемый проект **Supabase RUN30**, его **Project URL** и **Publishable key**, а также email/пароль аккаунта RUN30. Нужен **тот же проект**, новые таблицы создавать не надо.

Не публикуй пароли, refresh-токены, секретные ключи, личные GPX и дампы базы в GitHub. В исходниках нет твоих учётных данных.

## 1. Загрузка проекта на GitHub с Windows

### Рекомендуемый способ — GitHub Desktop

1. Установи GitHub Desktop: https://desktop.github.com/ и войди в GitHub.
2. Выбери **File → New repository**. Название, например, `RUN30-Native-iOS`; место — любая удобная папка на диске.
3. Нажми **Create repository**.
4. Распакуй ZIP, который предоставил ChatGPT, и **скопируй СОДЕРЖИМОЕ** папки `RUN30_Native_iOS` в созданную папку репозитория. На верхнем уровне должны лежать `project.yml`, `README_RU.md`, каталог `RUN30` и скрытый каталог `.github` с `workflows/build-ios.yml`.
5. В GitHub Desktop укажи сообщение, например `Initial RUN30 Native`, нажми **Commit to main**, затем **Publish repository**.
6. Если хочешь использовать бесплатные стандартные минуты GitHub Actions без учёта приватного тарифа — выбери **Public**. Код будет виден всем, поэтому никогда не добавляй туда ключи, пароли или маршруты. Private тоже возможен, но лимит/оплата macOS-минут зависит от тарифа.

### Без GitHub Desktop (если уже установлен Git)

Открой PowerShell в распакованной папке проекта и выполни:

```powershell
git init
git add .
git commit -m "RUN30 Native initial"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/RUN30-Native-iOS.git
git push -u origin main
```

Перед этим создай **пустой** репозиторий на GitHub и настрой авторизацию в Git. В команду `git remote` подставь свой GitHub-логин. Не вставляй Apple ID или Supabase-пароль в файлы репозитория.

## 2. Облачная сборка неподписанного IPA

1. Открой созданный репозиторий на github.com.
2. Открой вкладку **Actions** и разреши workflows, если GitHub предложит.
3. В левом списке выбери **Build unsigned iPhone IPA**.
4. Нажми **Run workflow → Run workflow** (ветка `main`).
5. Открой запущенный workflow. Дождись **зелёной галочки** (успешное завершение).
6. В нижней секции **Artifacts** нажми **RUN30-unsigned-IPA**. GitHub скачает ZIP-архив артефакта.
7. **Распакуй скачанный ZIP:** внутри должен оказаться файл **`RUN30-unsigned.ipa`**. Это не тот же ZIP, что исходники.

Команды, которые выполняет Actions: XcodeGen генерирует Xcode-проект, `xcodebuild` компилирует для реального iPhone с `CODE_SIGNING_ALLOWED=NO`, затем папка `Payload/RUN30.app` упаковывается в неподписанный IPA. Сборка не требует Apple Developer Program.

Если сборка упала, открой красный шаг, разверни лог и сохрани **первые ошибки компиляции**. Сообщения вроде `Code Signing Error` в шагах с `CODE_SIGNING_ALLOWED=NO` требуют отдельного разбора — сам IPA не подписывается до установки через Sideloadly.

## 3. Установка на iPhone через Sideloadly (Windows 11)

1. Скачай и установи **Sideloadly только с https://sideloadly.io/**.
2. По инструкции Sideloadly установи необходимые драйверы Apple. На Windows могут потребоваться веб-версии **iTunes и iCloud**, указанные на официальном сайте Sideloadly; Microsoft Store-версии иногда несовместимы.
3. Подключи iPhone **кабелем USB**, разблокируй его и нажми **«Доверять этому компьютеру»**.
4. Запусти Sideloadly. В списке устройств должен появиться iPhone.
5. Перетащи `RUN30-unsigned.ipa` в окно Sideloadly.
6. В поле Apple ID введи свой Apple Account; нажми **Start**. При необходимости выполни двухфакторную проверку Apple.
7. Если iPhone требует **«Режим разработчика / Developer Mode»**, открой **Настройки → Конфиденциальность и безопасность → Режим разработчика**, включи и перезагрузи iPhone. Этот пункт иногда появляется после первой попытки установки.
8. При запросе доверия перейди в **Настройки → Основные → VPN и управление устройством**, выбери соответствующий профиль разработчика и подтверди доверие.
9. Открой установленное приложение **RUN30** с домашнего экрана iPhone.

**Бесплатный Apple ID:** подпись обычно действует **7 дней**. Для продления запускай переподпись Sideloadly (возможно автообновление через Sideloadly Daemon при регулярном подключении к компьютеру). Данные должны оставаться при обновлении с тем же Bundle ID, но обязательно делай резервную копию важных маршрутов; **не удаляй приложение**, если данные ещё не синхронизированы.

## 4. Подключение к существующему Supabase

1. Запусти нативный RUN30 на iPhone → вкладка **Облако**.
2. Введи **Project URL** (`https://<project-ref>.supabase.co`) и **Publishable key** (`sb_publishable_...`, либо прежний anon JWT), которыми пользуешься в веб-RUN30. **Не используй** `secret`/`service_role`.
3. Нажми **«Сохранить проект»**.
4. Войди тем же **email и паролем RUN30**, что на компьютере (это пароль **аккаунта в Supabase Auth**, а не пароль GitHub или Apple ID).
5. Нажми **«Синхронизировать»**. На экране **Журнал** должны появиться прежние пробежки.
6. Если на устройстве были офлайн-изменения того же занятия, что уже изменено в облаке, в разделе «Конфликты» выбери свою или облачную версию.

Новые SQL-таблицы не требуются: используется существующая `public.run30_sync` и её правила RLS. Нативное приложение использует те же ключи `record:W-D`, `ready:W-I`, `startDate`, что и веб-версия, и передаёт маршруты в полях `gps.points`.

## 5. Проверка фонового GPS на улице

1. На iPhone открой **Настройки → Конфиденциальность и безопасность → Службы геолокации**; включи геолокацию. Для RUN30 выбери **«При использовании приложения»** и **«Точная геопозиция»** (если доступно).
2. В RUN30 открой вкладку **GPS**, выбери неделю и тренировку, нажми **«Начать GPS-пробежку»** в переднем плане.
3. Дождись статуса «GPS работает» и первых точек на карте.
4. Пройди **200–400 метров** на открытом воздухе и проверь километры, время и маршрут.
5. Не завершая, **заблокируй экран на 1–2 минуты**, пройди ещё немного. Разблокируй и проверь, продолжала ли линия маршрута записываться. Повтори более длительный тест до того, как полагаться на приложение в 30-километровом забеге.
6. **Завершить → Сохранить и синхронизировать**. Убедись, что пробежка появилась в журнале на веб-сайте RUN30.

При паузе GPS отключается. После возобновления между последней старой и новой точкой не будет ложной прямой линии. После аварийного закрытия приложения черновик сохраняется и при следующем открытии становится **приостановленным**; непрерывность в период закрытия восстановить нельзя.

### Ограничения фонового режима

- Core Location может продолжать обновлять GPS с заблокированным экраном **только во время уже начатой тренировки**. Приложение специально включает `allowsBackgroundLocationUpdates` и режим `location`.
- **Не смахивай RUN30 из списка запущенных приложений**: принудительное закрытие может остановить отслеживание. Низкий заряд, энергосбережение, слабый GPS и перезапуск системы тоже влияют на полноту маршрута.
- **Фоновая запись на реальном iPhone и реальная подпись через Sideloadly ещё не проверены** в этой поставке: для этого требуется сборка GitHub и твой iPhone. При некоторых бесплатных профилях подписи возможны ограничения или ошибки установки.
- Геолокация расходует батарею. На длительную тренировку возьми заряженный телефон и не полагайся на единственный источник GPS без пробной проверки.
- GPS имеет погрешность. RUN30 отбрасывает точки с погрешностью больше 50 м, со скоростью скачка больше 7 м/с, и соединения после больших разрывов сигнала.
- Ограничение прототипа — **5000 точек в одной пробежке**. Это может быть недостаточно для отдельных очень длительных тренировок; при достижении лимита запись координат останавливается.

## 6. Если возникла ошибка

| Ситуация | Действия |
|---|---|
| На GitHub не видно workflow | Проверь `.github/workflows/build-ios.yml` в **корне репозитория** и вкладку Actions |
| В Actions красная ошибка компиляции | Открой лог первого упавшего шага, сохрани ошибку; код не компилировался на Windows и требует проверки macOS |
| Sideloadly не видит iPhone | Разблокируй, нажми «Доверять», проверь кабель, Apple Devices / драйверы, перезапусти Sideloadly |
| IPA не устанавливается | Проверь, что в Sideloadly указан `.ipa` из ZIP артефакта; Developer Mode, профиль доверия, лимиты Apple ID |
| Не сохраняются пробежки в облако | Проверь статус «Офлайн», URL, Publishable key, логин и RLS `run30_sync` |
| GPS не показывает точки | Разреши геолокацию и точное местоположение, выйди на открытое место, проверь настройки iOS |
| Маршрут обрывается при блокировке | Проверь разрешения, фоновый режим сборки, выключи энергосбережение для теста; если сохраняется, потребуется диагностика на реальном устройстве |
| Приложение не открывается через 7 дней | Переподпиши через Sideloadly с тем же Bundle ID; не удаляй локальные данные |

```text

├── project.yml                  # конфигурация XcodeGen
├── RUN30/
│   ├── RUN30App.swift           # точка входа и вкладки

│   ├── GPSTracker.swift         # Core Location и запись в фоне

│   ├── Views.swift              # интерфейс
│   └── Info.plist               # разрешения и background location

├── scripts/validate_project.py  # статическая проверка проекта
└── README_RU.md                # эта инструкция
```
